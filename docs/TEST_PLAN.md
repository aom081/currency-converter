# แผนการทดสอบ (Test Plan) — เครื่องคำนวณค่าเงิน

| รายการ | รายละเอียด |
|---|---|
| ระบบที่ทดสอบ | เว็บแอปเครื่องคำนวณค่าเงิน (Vite + TypeScript) |
| เวอร์ชัน | 1.0.0 |
| ประเภทการทดสอบ | Functional / UI end-to-end (อัตโนมัติ) |
| เครื่องมือ | Playwright Test (TypeScript), Robot Framework + Browser library และ Selenium (Python + pytest) |

## 1. วัตถุประสงค์
ยืนยันว่าแอปคำนวณค่าเงินได้ถูกต้อง ติดตามสกุลเงินและแสดงการเปลี่ยนแปลงได้ถูกต้อง จัดการกรณี API ล่มได้อย่างปลอดภัย และใช้งานได้บนเดสก์ท็อปและมือถือ

## 2. ขอบเขต
**อยู่ในขอบเขต**
- การแปลงค่าเงิน (จำนวนเงิน เลือกสกุล สลับสกุล แสดงอัตรา)
- สถานะข้อมูล (สด/ออฟไลน์), ปุ่มรีเฟรช, อัปเดตอัตโนมัติ 60 วินาที
- รายการที่ติดตาม (เพิ่ม/ลบ, ▲▼ การเปลี่ยนแปลง, สกุลฐาน, การคงอยู่หลังรีโหลด)
- รายการสกุลเงินทั้งหมดและการค้นหา, การจำค่าที่เลือก
- การแสดงผลบนจอมือถือ (ไม่มี overflow แนวนอน)
- ธีม (สว่าง/มืด/ตามระบบ และการจำค่า)
- แจ้งเตือนราคาเป้าหมาย (ตั้ง/ลบ/ทริกเกอร์/ไม่ทริกเกอร์เมื่อออฟไลน์/แจ้งครั้งเดียว)
- กราฟย้อนหลัง 7/30/90 วัน (สถิติ ต่ำสุด สูงสุด เปลี่ยนแปลง และกรณีไม่มีข้อมูล)
- การแปลงเป็นหลายสกุลพร้อมกัน
- สกุลเงินเพิ่มเติมที่ API ส่งมานอกเหนือ 33 สกุลหลัก
- สลับภาษาไทย/อังกฤษ (ข้อความคงที่ ข้อความจากโปรแกรม ชื่อสกุลเงิน)
- เทียบกับเรทร้านแลกเงิน/ธนาคาร (ค่าธรรมเนียม % และคงที่)
- แชร์ลิงก์ (สร้างลิงก์ ซิงก์แถบที่อยู่ เปิดจากลิงก์ ข้ามพารามิเตอร์ที่ผิด)
- จัดเรียงรายการที่ติดตาม (กำหนดเอง ▲▼, แข็ง/อ่อนค่ามากสุด, รหัสสกุล)
- ส่งออก CSV (กราฟย้อนหลัง และประวัติของรายการที่ติดตาม)
- ใช้งานออฟไลน์ (อัตราที่บันทึกไว้/อัตราตัวอย่าง) และ PWA (manifest, service worker, เปิดออฟไลน์)

**นอกขอบเขต**
- ความถูกต้องของอัตราจากผู้ให้บริการ open.er-api.com และ Frankfurter (ใช้ mock แทน)
- Notification ของเบราว์เซอร์ (ทดสอบเฉพาะข้อความแจ้งในหน้า)
- การติดตั้งแอปจริงบนมือถือ/เดสก์ท็อป (ปุ่ม Install ของเบราว์เซอร์) — ตรวจเฉพาะว่า manifest ครบเงื่อนไข
- ความครบถ้วนของชื่อสกุลเงินใน Intl.DisplayNames ซึ่งต่างกันตามเบราว์เซอร์ (ตรวจเฉพาะชื่อ JPY)
- ประสิทธิภาพ/โหลด, ความปลอดภัยเชิงลึก, การทดสอบ accessibility ด้วยเครื่องมือเฉพาะ
- Safari/WebKit และอุปกรณ์จริง (ดูหัวข้อความเสี่ยง)

## 3. กลยุทธ์การทดสอบ
1. **Mock API ทุกการทดสอบ** เพื่อให้ผลคำนวณเท่าเดิมทุกครั้ง และสร้างสถานการณ์อัตราขึ้น/ลง/ล่มได้
2. **Playwright** ครอบคลุมทุกกรณี (TC ทั้ง 94 ข้อ) รันขนานกันบน Chromium และมือถือ (Pixel 5)
3. **Robot Framework** ครอบคลุมกรณีหลัก 77 ข้อ (smoke + regression) เขียนแบบ keyword-driven ให้ทีม QA อ่านง่าย รันบน Chromium
4. **Selenium (Python + pytest)** ครอบคลุม 88 ข้อ (ยกเว้น TC-DATA-05 ที่ต้องใช้นาฬิกาจำลอง, TC-THEME-05/06 ที่ต้องจำลองโหมดสีของระบบ, TC-SHARE-06 คลิปบอร์ด และ TC-PWA-02/03 ที่ต้องใช้ไฟล์ build จริง) ใช้ Page Object (`app_page.py`) และ mock server ตัวเดียวกับ Robot รันบน Chrome
5. ทุกชุดใช้ test case ID เดียวกัน เพื่อสอบย้อนกลับได้ (ดู `TEST_CASES.md`)
6. ทุกเทสต์เริ่มจากสภาพว่าง (context ใหม่ localStorage ว่าง) ไม่พึ่งลำดับการรัน

| ระดับ | ความหมาย | แท็ก |
|---|---|---|
| Smoke | ฟังก์ชันหลักต้องผ่านก่อนรันชุดเต็ม | `smoke` / `@smoke` |
| Regression | ทุกกรณี | ทั้งหมด |

## 5. ข้อมูลทดสอบ
อัตราจำลอง (ต่อ 1 USD): `USD=1, THB=35, JPY=150, EUR=0.9, GBP=0.8`

| กรณี | ค่าที่ใช้ | ผลที่คำนวณได้ |
|---|---|---|
| 1,000 USD → THB | 35 | 35,000 THB |
| 1,000 USD → JPY | 150 | 150,000 JPY |
| 1,000 THB → USD | 1/35 | 28.5714 USD |
| JPY เทียบ THB (ฐาน THB) | 35/150 | 0.233333 |
| JPY เปลี่ยน 150 → 140 | 35/140 = 0.25 | ▲ +7.143% |
| JPY เปลี่ยน 150 → 160 | 35/160 = 0.21875 | ▼ -6.250% |
| เทียบเรทร้าน 1,000 USD → THB (เรทกลาง 35) | เรทร้าน 34 | 34,000 THB, ส่วนต่าง -1,000 (-2.857%) |
| เทียบเรทร้าน + ค่าธรรมเนียม | เรทร้าน 34 + 1% / คงที่ 5 USD | 33,660 (-3.829%) / 33,830 (-3.343%) |
| แชร์ลิงก์ | 250 EUR → JPY | `?amt=250&from=EUR&to=JPY` → 41,666.67 JPY |
| เรียงตามแข็ง/อ่อนค่า | JPY=140, EUR=0.95, GBP คงที่ | JPY +7.143%, GBP 0%, EUR -5.263% |
| สกุลเพิ่มเติม | CZK=22 | 1,000 USD = 22,000 CZK, 34 สกุลในรายการ |
| แจ้งเตือน JPY/THB "สูงกว่า 0.24" | JPY=140 → 0.25 | ทริกเกอร์ |
| แจ้งเตือน JPY/THB "ต่ำกว่า 0.23" | JPY=160 → 0.21875 | ทริกเกอร์ |
| กราฟย้อนหลัง USD→THB | ต้นช่วง 0.9×35, ปลายช่วง 35 | ต่ำสุด 31.5, สูงสุด 35, +11.111% (30 วัน = 31 จุด) |
| แปลง 1,000 USD เป็น JPY/EUR/GBP | 150 / 0.9 / 0.8 | 150,000 / 900 / 800 |

กรณีออฟไลน์ใช้อัตราสำรองในโค้ด (THB = 33.5) จึงได้ 33,500 THB

## 6. เกณฑ์เริ่มและเสร็จสิ้นการทดสอบ
**เริ่ม:** โค้ด build ผ่าน (`npm run build`), ติดตั้งแพ็กเกจและเบราว์เซอร์ครบ
**ผ่าน (Exit):**
- Smoke ผ่าน 100%
- Regression ผ่าน ≥ 95% และไม่มีข้อบกพร่องระดับ Critical/High ที่ยังเปิดอยู่
- ทุกข้อบกพร่องที่เหลือมีแผนแก้ไขหรือยอมรับความเสี่ยงโดยเจ้าของผลิตภัณฑ์

## 7. ระดับความรุนแรงของข้อบกพร่อง
| ระดับ | ตัวอย่าง |
|---|---|
| Critical | คำนวณผิด / หน้าเว็บใช้งานไม่ได้ |
| High | ติดตามสกุลเงินไม่ได้ / ▲▼ แสดงผิด |
| Medium | ค้นหาไม่ตรง / ไม่จำค่าที่เลือก |
| Low | ข้อความหรือการจัดวางเล็กน้อย |

## 8. ความเสี่ยงและข้อควรระวัง
| ความเสี่ยง | แนวทางลดความเสี่ยง |
|---|---|
| ไม่ได้ทดสอบกับ API จริง | ทำ smoke ด้วยมือเป็นครั้งคราวกับ open.er-api.com |
| ข้อความภาษาไทยใน selector/assert เปลี่ยนแล้วเทสต์พัง | รวมข้อความไว้ใน helper/resource; แก้จุดเดียว |
| เทสต์อัตโนมัติ 60 วินาทีพึ่ง fake clock | ใช้ `page.clock` (Playwright ≥ 1.45) ไม่รอจริง |
| Selenium ดักเครือข่ายและจำลองโหมดสีของระบบไม่ได้ จึงใช้ mock server และไม่ครอบคลุม TC-DATA-05, TC-THEME-05/06 (และกรณี 'JSON ไม่มี rates' ของ TC-DATA-03) | ใช้ Playwright ครอบคลุมกรณีเหล่านี้ |
| กราฟย้อนหลังพึ่ง Frankfurter v1 ซึ่งมีเฉพาะบางสกุล และอาจเปลี่ยนเวอร์ชันในอนาคต | แสดงข้อความเมื่อไม่มีข้อมูล, เปลี่ยน URL ได้ผ่าน `VITE_HISTORY_URL`, ทดสอบด้วย mock (TC-CHART-05/06) |
| แจ้งเตือนทำงานเฉพาะตอนเปิดหน้าไว้ (ไม่มี server) | ระบุไว้ในหน้าเว็บ; ถ้าต้องการแจ้งเตือนตอนปิดหน้า ต้องมีบริการฝั่งเซิร์ฟเวอร์ |
| Service worker ทำงานเฉพาะ production จึงทดสอบ PWA ได้เฉพาะกับไฟล์ที่ build | ชุด `playwright.pwa.config.ts` build + preview ให้เอง; Robot/Selenium ตรวจเฉพาะ manifest |
| ดาวน์โหลด CSV ใน Selenium ใช้ Chrome DevTools Protocol (Chrome เท่านั้น) และ Robot ไม่ครอบคลุม | ใช้ Playwright เป็นหลักสำหรับกลุ่ม CSV |
| ผลของ `Intl.DisplayNames` ต่างกันตามเบราว์เซอร์/เวอร์ชัน | ทดสอบเพียงคำว่า "Yen"/"เยน" และตัวสกุล ไม่ตรวจชื่อเต็ม |
| ไม่มี WebKit/Safari | เพิ่มโปรเจ็กต์ `webkit` ใน `playwright.config.ts` ได้เมื่อต้องการ |
| อัตราสำรองในโค้ดเปลี่ยน → TC-DATA-02 ไม่ผ่าน | อัปเดตค่าคาดหวังให้ตรง `src/currencies.ts` |

## 9. ผลลัพธ์ที่ส่งมอบ
- แผนนี้, `TEST_CASES.md`, โค้ดทดสอบใน `tests/`
- รายงาน Playwright: `playwright-report/` (HTML), trace/screenshot ของเทสต์ที่ล้มเหลวใน `test-results/`
- รายงาน Robot: `results/robot/report.html`, `log.html`, `output.xml`
- รายงาน Selenium: `results/selenium/report.html`

## 10. วิธีรัน
```bash
# ติดตั้งครั้งแรก
npm install
npx playwright install
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
rfbrowser init

# Playwright
npm run test:e2e                          # ทั้งหมด
npx playwright test --grep @smoke         # เฉพาะ smoke
npx playwright test --project=chromium    # เฉพาะ Chromium
npm run test:e2e:report                   # เปิดรายงาน
npm run test:e2e:pwa                      # ทดสอบ PWA (build + preview พอร์ต 4173 แยกจากชุดหลัก)

# Robot Framework (เปิด mock + แอปให้เองอัตโนมัติ)
npm run test:robot
robot --include smoke --outputdir results/robot tests/robot
robot -v HEADLESS:False --outputdir results/robot tests/robot   # ดูเบราว์เซอร์ขณะรัน

# Selenium (ใช้ venv และ pip install -r requirements.txt เดียวกับ Robot ไม่ต้อง rfbrowser init)
pytest                                           # ทั้งหมด (Chrome headless)
pytest -m smoke                                  # เฉพาะ smoke
set HEADLESS=0 && pytest                         # ดูเบราว์เซอร์ (cmd) | macOS/Linux: HEADLESS=0 pytest
npm run test:selenium                            # สร้างรายงาน HTML ใน results/selenium/
```
